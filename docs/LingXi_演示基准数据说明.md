# LingXi 演示基准数据说明

## 1. 结论

当前项目已经使用 MySQL 作为正式演示数据库。旧 SQLite 文件 `lingxi.db` 中确实有历史数据，但其中混有早期 Vue/IHRM 测试资源、旧资源类型和临时测试账号，不适合作为比赛演示底库原样迁移。

因此当前采用更稳妥的方案：

```text
MySQL 正式库 + 人工智能导论课程知识库 + 演示基准数据 seed 脚本
```

这样可以保证每次演示前都能恢复到一套稳定、完整、能覆盖主要功能的状态。

## 2. 数据库位置

当前 `.env` 使用：

```env
DATABASE_URL=mysql+pymysql://root@127.0.0.1:3306/lingxi?charset=utf8mb4
```

真实数据写入本机 MySQL 的 `lingxi` 数据库。

旧的 `lingxi.db` 只是历史 SQLite 文件，不建议提交，也不建议作为正式演示数据源。

## 3. 重建演示基准数据

进入后端目录：

```bash
cd /Users/rinko/Documents/软件杯/LingXi-Backend
source .venv/bin/activate
python scripts/seed_demo_data.py
```

脚本会执行：

1. 初始化数据库表结构。
2. 同步《人工智能导论》初始课程知识库。
3. 重置并写入演示学生相关数据。
4. 写入资源、审核、反馈、规划、待办、评价和聊天历史。

注意：该脚本会重置 `student` 和 `demo_basic` 相关的演示数据，包括聊天、规划、待办和评价记录；也会清理 `test_` 开头的接口测试账号、临时生成资源、临时分类和临时反馈。它不会改动真实 `.env`，也不会依赖旧 SQLite。

## 7. 推荐演示顺序

1. 启动后端和前端。
2. 登录 `student / 123456`。
3. 展示历史对话和 AI 学习助手。
4. 进入资源库，展示《人工智能导论》初始知识库资源。
5. 打开“第 7 章 多模态资源生成与智能体协同”或“监督学习多模态学习包”。
6. 点击导出 PPT。
7. 进入规划页，展示个性化补弱路线和待办。
8. 进入评价页，展示历史诊断和分数变化。
9. 进入个人画像页，展示知识点概括和画像信息。
10. 切换登录 `admin / 123456`。
11. 打开控制台，展示 7 个待处理事项。
12. 进入资源审核，查看内容安全自检并通过一个资源。
13. 进入分类审核和反馈中心，展示治理能力。
14. 回到学生端资源库，验证审核通过后的资源可见。

## 9. 注意事项

1. 演示前建议先运行一次 `python scripts/seed_demo_data.py`，保证数据状态统一。
2. 不要提交 `.env`。
3. 不要提交 `lingxi.db`。
4. 不要提交 `.venv` 和 `node_modules`。
5. 如果现场要切换模型，需要修改 `.env` 后重启后端。
