> 系统名称：LingXi 灵析学伴  
> 开发类型：Web 应用，前后端分离，多智能体学习资源生成系统

## 1. 赛题目标理解

赛题要求参赛团队借助大模型、多模态生成、AI 工具和多智能体协同机制，构建面向高等教育的个性化学习资源体系，解决传统学习资源繁杂、个体差异难以适配、学习路径缺乏指导、学习效果难以持续评估的问题。

本系统的设计目标是：

```text
让学生不用填写复杂表单，而是通过自然语言对话表达目标、困惑和学习状态；
系统自动形成动态画像，检索课程知识库依据，生成个性化辅导、资源和路径；
生成内容进入管理员审核，保证质量和安全；
学习评价结果反向更新画像与路线，形成持续优化闭环。
```

## 3. 基本功能需求匹配

### 3.1 对话式学习画像自主构建

赛题要求：

- 摒弃传统繁琐表单。
- 通过自然语言对话抽取学生特征。
- 构建不少于 6 个维度的动态学生画像。
- 支持画像随学随新。

系统实现：

- 学生在首页直接输入学习问题、目标或困惑。
- 意图识别 Agent 判断学习意图和主题。
- 画像建模 Agent 结合对话、学习时长、评价记录、规划完成情况和待办完成情况构建画像。
- 每轮对话、每次评价、每次规划执行都会更新画像。

画像维度覆盖：

1. 知识基础
2. 学习目标
3. 认知水平
4. 认知风格
5. 高频主题
6. 知识短板
7. 实践能力
8. 学习专注度
9. 自驱探索力
10. 学习强度

匹配度：已完成，并超过“不少于 6 个维度”的要求。

### 3.2 多智能体协同的资源生成

赛题要求：

- 系统须体现多智能体架构。
- 依据学生提供的专业、课程内容、知识短板和学习需求生成个性化资料。
- 不同角色智能体协作完成至少 5 种类型资源。

系统实现的 Agent：

| Agent | 职责 |
|---|---|
| 意图识别 Agent | 判断学生输入属于概念讲解、路径规划、生成资源、练习巩固、实操训练或综合学习 |
| 知识检索 Agent | 检索课程知识库和已审核资源，形成回答依据 |
| 画像建模 Agent | 更新动态学生画像 |
| 学习辅导 Agent | 调用大模型生成个性化答疑 |
| 路径规划 Agent | 生成学习步骤和路线 |
| 资源设计 Agent | 规划资源类型和主题 |
| 内容安全 Agent | 检查敏感风险、来源标注、结构完整度、防幻觉风险 |
| 评价诊断 Agent | 生成学习评价、薄弱点和补救建议 |

资源类型：

1. 专业课程讲解文档
2. 知识点思维导图
3. 不同类型练习题目
4. 拓展阅读材料
5. 多模态学习包
6. 错题诊断与学习反馈报告
7. 学科实践应用任务

匹配度：已完成，资源类型超过要求。

### 3.3 个性化学习路径规划和资源推送

赛题要求：

- 整合生成资源。
- 结合学生专业、进度、掌握情况和偏好规划动态学习路径。
- 基于画像实现资源精准推送。

系统实现：

- 对话触发路径规划。
- 规划页展示 AI 生成路线。
- 路线支持学生修改、删除、插入任务和调整状态。
- 资源与路线联动生成。
- 生成资源先进入管理员审核，通过后进入学生资源库。
- 学习评价低分时可生成补弱路线。

匹配度：已完成。

### 3.4 智能辅导加分项

赛题要求：

- 学生遇到问题时可即时答疑。
- 可结合多模态形式提供解释。

系统实现：

- 首页聊天支持即时学习问答。
- 支持 Markdown、代码块、Mermaid 流程图等展示。
- 回答前检索课程知识库依据。
- 历史消息保留处理链路和知识库依据。

匹配度：已完成基础版。

### 3.5 学习效果评估加分项

赛题要求：

- 跟踪学习行为、练习情况、资源反馈。
- 用大模型进行多维评估。
- 根据评估结果调整资源和计划。

系统实现：

- 评价页支持平台自动诊断。
- 支持学生补充线下错题。
- 生成诊断分数、掌握等级、薄弱点和建议。
- 评价结果进入历史。
- 低分时生成补弱路线和诊断资源。
- 画像读取评价记录并随学更新。

匹配度：已完成。

## 7. 创新价值

### 7.1 不是简单聊天机器人

系统把“问答”扩展成“画像、依据、路线、资源、评价、审核”的闭环。

### 7.2 多模态不盲目承诺视频

系统没有强行把所有内容做成视频，而是把多模态拆成更可落地的学习表达：

- 文字讲解
- 知识结构图
- 流程图
- 代码注释
- 分步题解
- PPT 页纲
- 真实 PPT 导出
- 实践任务

这种设计更适合比赛演示和真实学习场景。

### 7.3 防幻觉链路可见

学生能看到知识库依据，管理员能看到内容安全自检。系统不是直接把大模型输出当最终答案，而是加入课程知识库和审核治理。

### 7.4 管理端体现人机协同

资源生成后不直接发布，而是进入管理员审核队列。这样更符合教育内容发布场景。

## 9. 边界和答辩说明

需要主动说明：

1. 系统当前以 Web 应用形式提交，适合桌面浏览器演示。
2. 多模态资源当前重点体现为多表达形态和 PPT 导出，不把实时视频生成作为常规功能，以保证稳定性和成本可控。
3. 当前防幻觉机制为知识库依据链、规则自检和管理员审核，后续可升级向量库和更强内容安全模型。
4. 当前演示使用本地 MySQL 和本地前后端服务，属于比赛可运行环境，不等同于生产云部署。
5. 默认账号密码用于演示，正式上线应接入密码加密、权限细分和安全审计。
